당신은 Our Taiwan 2026 커플 여행 웹앱을 인수하는 개발자입니다.

저장소: https://github.com/myungbull/our-taiwan-2026
운영 사이트: Our Taiwan 2026, 현재 버전 18
항상 GitHub `main`의 최신 커밋에서 시작하세요. 앱 기능 기준 커밋은 98e48cdb429710b871628047d80a1ec24f0717e4이며, 이후 인수인계 문서와 CI 설정이 추가됐습니다.

시작 전에 README.md, docs/DEVELOPER_HANDOFF.md, docs/OPEN_ITEMS.md, docs/DEPLOYMENT.md를 읽으세요. 저장소 기록과 현재 Sites 프로젝트 상태를 대조하고, 문서와 다르면 실제 상태를 우선해 문서를 갱신하세요.

목표는 미해결 기술 항목을 마무리하고, 검증한 변경을 기존 비공개 Sites 운영 사이트에 안전하게 배포하는 것입니다.

우선순위:
1. 현재 운영 사이트의 소유권·custom 접근 정책·D1/R2 바인딩·시크릿 존재 여부를 읽기 전용으로 확인합니다. 두 허용 계정만 접근 가능한 기존 정책과 데이터를 보존합니다.
2. AccuWeather `ACCUWEATHER_API_KEY`의 안전한 운영 설정 여부를 확인합니다. 키가 없다면 사용자가 제공한 키를 비밀 입력 경로로 설정하도록 요청하고, 코드·커밋·문서·로그에는 절대 쓰지 않습니다. CWA는 추가하지 않습니다.
3. 11/8 Taipei 시간 전환, 11/18~22 예보 범위, API 실패·캐시·키 누락 동작을 테스트합니다. 현재 자동 테스트가 부족하면 작은 테스트부터 추가합니다.
4. 두 허용 계정의 별도 세션에서 아이디어 찬성/대기목록/일정 선택, 예산·체크리스트 동기화를 확인합니다. iPhone Safari에서는 사진·영상 보관함 선택, 압축, 업로드, 비공개 조회, 영상 재생, 사진 확대·삭제 흐름을 확인합니다. 실제 계정/기기가 없으면 확인한 척하지 말고 한계를 기록합니다.
5. `npm run typecheck`, `npm run test:state`, `npm run build`를 실행합니다. `npm run lint`의 알려진 기존 실패는 docs/OPEN_ITEMS.md에 있는 기준과 비교해 새 오류를 구분하고, 전역 규칙을 무시해 통과시키지 않습니다.
6. 운영 배포는 GitHub push만으로 되지 않습니다. Sites 커넥터와 기존 프로젝트 권한이 있으면 docs/DEPLOYMENT.md와 현재 Sites 절차를 따라 정확히 검증한 커밋을 기존 사이트에 배포합니다. 접근 모드를 public으로 바꾸거나 허용 이메일·DB·비공개 R2를 교체하지 않습니다. 프로젝트 권한이 없다면 검증 가능한 빌드/아카이브까지 준비하고 배포가 막힌 이유를 적습니다.
7. 익명 사용자의 401/로그인 차단, 두 허용 계정의 공동 API, 운영 버전·커밋을 확인하고 결과를 기록합니다. 변경은 작업 브랜치에서 커밋하고 GitHub에 푸시합니다.

중요 제한:
- GitHub Pages는 대상이 아닙니다. 독립 Cloudflare 배포도 Sites 로그인 식별자를 대체하는 인증 설계와 D1/R2 이전 없이는 운영할 수 없습니다.
- `ALLOWED_EMAILS`, `ACCUWEATHER_API_KEY`, 실제 예약·카드 정보, 개인 사진을 저장소에 넣지 않습니다. 운영 비밀은 Sites의 비밀 설정을 사용합니다.
- 공개 저장소에는 이미 여행 날짜/일정, 항공편 번호·시간, 운임이 들어 있습니다. 더 많은 개인정보를 추가하지 마세요.
- iPhone 백그라운드 지오펜스와 ChatGPT 앱의 iOS 공유 시트 노출을 보장하지 마세요. 현재 수동 대체 흐름을 정확히 설명합니다.

마지막 응답에는 변경 파일, 검증 결과, 해결/미해결 항목, 커밋 SHA, 배포 URL과 버전(실제 배포한 경우), 접근 정책 확인 결과를 포함하세요.
